# Restate v1.7.4 Release Notes

## Highlights

- **Reliable vqueue refills**: Queued entries are no longer missed when concurrent updates move an entry beyond an in-progress refill's overlay horizon.
- **Stable failure detection during startup**: Node startup time is no longer counted as missed gossip intervals, preventing healthy peers from being incorrectly considered dead and starting nodes from reporting themselves as isolated.
- **Fewer partition-store write stalls**: Partition stores now tolerate more RocksDB compaction debt before slowing or stopping writes, improving write availability for large partitions.
- **AWS MSK IAM authentication**: Kafka ingress can now authenticate to Amazon MSK using IAM credentials and SigV4-signed OAUTHBEARER tokens.
- **Pause suspended invocations from the CLI**: `restate invocations pause` now selects suspended invocations in addition to running and backing-off invocations.

## New Features

### AWS MSK IAM Authentication for Kafka Ingress

Kafka ingress can now authenticate to Amazon Managed Streaming for Apache Kafka (MSK) using AWS IAM. Restate generates SigV4-signed SASL/OAUTHBEARER tokens and refreshes them automatically.

Configure the Kafka cluster to use OAUTHBEARER and select the `msk-iam` provider:

```toml
[[ingress.kafka-clusters]]
name = "my-msk-cluster"
brokers = ["SASL_SSL://<broker>:9098"]
"security.protocol" = "SASL_SSL"
"sasl.mechanisms" = "OAUTHBEARER"
"sasl.oauthbearer.config" = "provider=msk-iam,region=us-east-1"
```

By default, Restate uses the standard AWS credential chain, including environment variables, web identity credentials such as IRSA, and instance profiles. To select a named AWS profile explicitly, add it to the provider configuration:

```toml
"sasl.oauthbearer.config" = "provider=msk-iam,region=us-east-1,profile=my-profile"
```

The region defaults to `us-east-1` when omitted. Existing OAUTHBEARER configurations handled by librdkafka, including OIDC authentication, continue to work unchanged. MSK IAM support is included in the standard Restate server build and does not require a feature flag.

_Related: [#5089](https://github.com/restatedev/restate/pull/5089)_

## Improvements

### CLI Support for Pausing Suspended Invocations

`restate invocations pause` now selects suspended invocations in addition to running and backing-off invocations.

When vqueues are enabled, pausing a suspended invocation moves it to the paused state. Resuming it re-invokes the invocation and replays its journal. Without vqueues, pausing a suspended invocation remains a successful no-op and is reported as already paused.

### Higher Partition-Store Compaction Limits

Partition stores now tolerate substantially more RocksDB compaction debt before applying a write slowdown or stopping writes. The soft pending-compaction limit is now 512 GiB and the hard limit is 2 TiB, matching the log server's behavior.

This improves write availability for large partitions when compaction falls behind. It can allow greater temporary disk usage and may reduce read performance while compaction debt remains high. No configuration or migration changes are required.

## Bug Fixes

### Reliable VQueue Refills During Concurrent Updates

Fixed a race in asynchronous vqueue refills where concurrent removals and additions could move a queued entry beyond the refill's overlay horizon. The scheduler could then incorrectly mark the queue as empty and miss the remaining entry.

The queue is now considered exhausted only when the refill reaches the end of storage and no entries remain beyond the overlay horizon. Queued invocations are therefore recovered by the next refill as expected. No configuration or migration changes are required.

### Failure Detector Startup Timing

The failure detector now resets its gossip timing when the node becomes ready. Time spent starting node roles is no longer counted as missed gossip intervals or as time without received gossip, preventing a starting node from incorrectly considering healthy peers dead or itself isolated.

No configuration or migration changes are required.

_Related: [#5156](https://github.com/restatedev/restate/issues/5156)_
