## Behavioral Changes

### Override Services Trace Resource Attributes

Resource attributes attached to services traces, emitted for deployed handlers and controlled by `tracing-services-endpoint` or `tracing-endpoint`, now honor the standard OpenTelemetry environment variables:

- `OTEL_SERVICE_NAME` sets `service.name`.
- `OTEL_RESOURCE_ATTRIBUTES`, in the format `key1=value1,key2=value2,...`, sets any resource attribute, including `service.name`, `service.namespace`, `service.instance.id`, and `service.version`.

User-provided values now take precedence over Restate's defaults. When both variables set `service.name`, `OTEL_SERVICE_NAME` takes precedence over `OTEL_RESOURCE_ATTRIBUTES`.

The defaults remain:

- `service.name=Restate`
- `service.namespace=Restate`
- `service.instance.id=<cluster>/<node>`
- `service.version=<version>`

Previously, Restate overwrote user-provided values for these four `service.*` attributes. Honoring them allows observability pipelines to use a custom `service.name` for routing, dashboards, or adoption metrics.

**Impact on users:**

- Deployments without these environment variables retain the existing defaults.
- Deployments setting `OTEL_SERVICE_NAME` or `service.*` attributes in `OTEL_RESOURCE_ATTRIBUTES` now use those values for services traces.
- Runtime traces, controlled by `tracing-runtime-endpoint`, are unchanged. Their `service.name` remains `<role>@<node-name>` to preserve per-node runtime identity.
