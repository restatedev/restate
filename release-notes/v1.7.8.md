# Restate v1.7.8 Release Notes

## Highlights

- **Safer partition-store maintenance**: Orphaned journal completion-index cleanup now stops on storage errors instead of risking incorrect cleanup or marking an incomplete scan as complete.
- **Consistent invocation retention**: An opt-in feature applies configured completion and journal retention when queued or delayed invocations are killed or cancelled.
- **Lower partition-processor memory usage**: Partition processors now share matching schema objects instead of retaining duplicate copies.

## Behavioral Changes

### Opt-in Retention for Terminated Pre-flight Invocations

Restate can now apply an invocation's configured completion and journal retention when the invocation is killed or cancelled before it starts running. This covers invocations that are queued while waiting for a Virtual Object or Workflow key, queued for a concurrency slot, or scheduled for later execution.

Previously, terminating these invocations immediately removed their invocation status and journal, regardless of the configured retention. This made their terminal result unobservable and allowed an idempotency key or Workflow key to be reused immediately.

The behavior is disabled by default in v1.7.8. Enable it with:

```toml
[common]
experimental-enable-preflight-invocation-termination-retention = true
```

With the option enabled:

- Re-submitting an idempotent invocation within its completion-retention period returns the retained `KILLED` or `CANCELED` result instead of starting a new invocation.
- Cancelling a queued or delayed Workflow submission retains the Workflow key for its completion-retention period. Re-submitting the same key during that period returns `409 Conflict` instead of starting the Workflow.
- Terminated pre-flight invocations remain available through introspection until their retention expires, including their journals when journal retention is non-zero.

Enabling this option applies a persistent partition feature that requires Restate Server v1.7.8 or newer. After the feature barrier has been applied, do not downgrade the cluster to an earlier version.

_Related: [#5104](https://github.com/restatedev/restate/issues/5104), [#5230](https://github.com/restatedev/restate/pull/5230)_

### Tokio Task Dumps Disabled in Shipped Binaries

Shipped `restate-server` binaries no longer produce tokio task backtraces when they receive `SIGUSR2`. The server logs that task dumping is unavailable instead.

Tokio task dumping re-polls live task futures while collecting backtraces. On Restate's current-thread runtimes, this could re-enter a scheduler and crash the process. Disabling the diagnostic removes that risk.

`SIGUSR1` configuration dumps and `SIGHUP` RocksDB flush and compaction remain unaffected. If you previously used `SIGUSR2` to investigate stuck tasks, use metrics, tracing, and logs instead. No configuration change is required.

_Related: [#5235](https://github.com/restatedev/restate/issues/5235), [#5236](https://github.com/restatedev/restate/pull/5236)_

## Improvements

### Reduced Partition-processor Schema Memory

Partition processors now reuse the global in-memory schema when its version matches their persisted schema. This best-effort deduplication reduces the steady-state memory consumed by duplicate schema objects across partitions.

The optimization does not eliminate the temporary memory used while initially deserializing a partition's schema. No configuration or migration changes are required.

_Related: [#5246](https://github.com/restatedev/restate/pull/5246)_

### Advanced RocksDB Merge Tuning

The worker storage configuration adds the advanced `rocksdb-max-successive-merges` option. It limits how many successive merge operands RocksDB keeps in a memtable before calculating and inserting the key's merged value. Tuning this can help workloads with a single very hot VQueue.

The option defaults to `5000`, preserving the previous hard-coded behavior. It is intentionally omitted from the generated configuration schema while more efficient partial merging is under development. Most deployments should retain the default.

```toml
[worker.storage]
rocksdb-max-successive-merges = 5000
```

_Related: [#5247](https://github.com/restatedev/restate/pull/5247)_

### Restate UI 1.0.22

The bundled Restate UI is updated from **v1.0.21** to **v1.0.22**. This release fixes invocation query planning when VQueues are not enabled.

No configuration or migration changes are required.

_Related: [Restate UI v1.0.22](https://github.com/restatedev/restate-web-ui/releases/tag/v1.0.22), [UI #745](https://github.com/restatedev/restate-web-ui/pull/745), [#5233](https://github.com/restatedev/restate/pull/5233)_

## Bug Fixes

### Fail-safe Orphaned Journal Index Cleanup

Orphaned journal completion-index cleanup now propagates RocksDB iterator and point-read errors. Previously, an iterator error could be mistaken for the normal end of a scan, while a failed journal lookup could cause a live journal to be classified as absent.

The cleanup now checks each invocation's journal ownership sentinel, stops on storage errors, and reports scan progress alongside deletion counts. This prevents incorrect cleanup and avoids marking an incomplete scan as complete. No configuration or migration changes are required.

_Related: [#5237](https://github.com/restatedev/restate/issues/5237), [#5242](https://github.com/restatedev/restate/pull/5242)_

### Support Empty Virtual Object Keys in Stored Locks

Restate now correctly decodes persisted VQueue lock names for Virtual Objects with an empty key. Previously, encountering one of these lock names could disrupt the partition.

Existing data remains compatible and no configuration or migration changes are required.

_Related: [#5245](https://github.com/restatedev/restate/pull/5245)_

### Correct Per-database RocksDB Memory Metrics

The following RocksDB memtable metrics are now scoped to the database identified by their labels instead of incorrectly aggregating memory across databases:

- `rocksdb_memory_approx_memtable_bytes`
- `rocksdb_memory_approx_memtable_unflushed_bytes`
- `rocksdb_memory_approx_memtable_readers`

The reported values also no longer include cache memory, which is already exposed through the write-buffer-manager metrics. Dashboards and alerts may observe lower, correctly scoped values after upgrading. No configuration changes are required.

_Related: [#5241](https://github.com/restatedev/restate/pull/5241)_

### Correct Keyed Invocation Filters in the CLI

Batch invocation commands now correctly interpret two-component targets such as `MyObject/myKey`. The CLI selects all handlers for the keyed Virtual Object or Workflow while continuing to treat `MyService/myHandler` as an exact service invocation target.

This fixes keyed target selection for `cancel`, `kill`, `pause`, `resume`, `purge`, and `restart-as-new`. No configuration or migration changes are required.

_Related: [#3752](https://github.com/restatedev/restate/issues/3752), [#5232](https://github.com/restatedev/restate/pull/5232)_
