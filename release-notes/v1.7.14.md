# Restate v1.7.14 Release Notes

## Highlights

- **Distrust of compromised emSign (eMudhra) intermediate certificates**: Restate no longer accepts TLS certificates issued through the emSign intermediates whose private keys have become public.
- **TLS library security fixes**: The bundled TLS library is updated to address several recently disclosed vulnerabilities.

## Security Fixes

### Reject Certificates Issued Through Compromised emSign Intermediates

The private keys of several emSign (eMudhra) intermediate certificate authorities are publicly known, so anyone can use them to issue certificates that impersonate any server. Restate now rejects any certificate chain that passes through these intermediates, including their cross-signed variants, on all outgoing TLS connections, such as calls to service deployments, AWS Lambda, and object stores.

No action is required. A server presenting a certificate from one of these intermediates will now fail the TLS handshake; replace such certificates with ones from a trusted CA.

_Related: [RUSTSEC-2026-0381](https://rustsec.org/advisories/RUSTSEC-2026-0381), [RUSTSEC-2026-0382](https://rustsec.org/advisories/RUSTSEC-2026-0382), [RUSTSEC-2026-0383](https://rustsec.org/advisories/RUSTSEC-2026-0383)_

### TLS Library Security Update

The TLS library (rustls) is updated to 0.23.46, which fixes TLS secrets being exposed in debug output, a pre-authentication memory allocation of up to 1 GiB during certificate decompression, and an unauthenticated downgrade of later connections to classical key exchange.

_Related: [RUSTSEC-2026-0346](https://rustsec.org/advisories/RUSTSEC-2026-0346), [RUSTSEC-2026-0347](https://rustsec.org/advisories/RUSTSEC-2026-0347), [RUSTSEC-2026-0348](https://rustsec.org/advisories/RUSTSEC-2026-0348), [RUSTSEC-2026-0349](https://rustsec.org/advisories/RUSTSEC-2026-0349)_
